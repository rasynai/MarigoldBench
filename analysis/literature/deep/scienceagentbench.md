## Section-by-section notes

**Abstract (lines 13–37).** Introduces ScienceAgentBench: 102 tasks extracted from 44 peer-reviewed publications in four disciplines, validated by nine subject matter experts. Target output unified as a self-contained Python program. Evaluates five open-weight/proprietary LLMs under three frameworks (direct prompting, OpenHands CodeAct, self-debug). Given three attempts per task, best agent solves 32.4% independently, 34.3% with expert knowledge. OpenAI o1-preview reaches 42.2% but at >10x the cost. Two data-contamination mitigation strategies are claimed.

**1 Introduction (lines 38–162).** Motivates rigorous per-task assessment before end-to-end automation claims (explicit foil: Lu et al. 2024 "The AI Scientist"). Three design principles: (1) scientific authenticity via co-design with nine experts (senior PhD students and professors); (2) rigorous graded evaluation (program, execution results, costs; plus per-task step rubrics); (3) careful multi-stage quality control plus two contamination-mitigation strategies. Figure 1 sub-task distribution: Data Processing (23), Model Development (23), Data Analysis (59), Information Visualization (65); finer: Feature Engineering (20), Feature Selection (2), Deep Learning (14), Machine Learning (9), Statistical Analysis (9), Geospatial Analysis (12), Data Visualization (45), Map Visualization (18), Computational Analysis (38), Data Selection (1), Molecule Visualization (2) — each task comprises one or more sub-tasks and "requires successful completion of all sub-tasks to achieve the task goal." Key claim on human effort: a trained annotator needs at least 2.5–3 hours on average to adapt an existing program; an agent drafts within ~10 minutes. Headline: Claude-3.5-Sonnet with self-debug solves 10.8% more tasks than with OpenHands CodeAct at 17x lower API cost.

**2 ScienceAgentBench / 2.1 Problem Formulation (lines 163–195).** Agent gets natural-language instruction + dataset + optional expert knowledge; must emit a standalone Python file. Four instance components (Figure 2): (a) Task Instruction — deliberately concise, avoids unnecessary detail to retain open-endedness; (b) Dataset Information — directory structure + content preview; (c) Expert-Provided Knowledge — term explanations, formulas, example tool usages; optional input; (d) Annotated Program — adapted from open-source repo of a peer-reviewed publication; self-contained; agents need not use the same tools.

**2.2 Data Collection (lines 196–258).** Nine graduate students annotate tasks in Bioinformatics, Computational Chemistry, Geographical Information Science, Psychology & Cognitive Neuroscience, from publications with permissively licensed code/data. Five annotation steps: identify self-contained code example; collect/preprocess datasets; annotate reference program; implement executable task-specific success criteria + GPT-4o-drafted rubrics; write instruction and dataset info. Funnel: 110 gathered → 4 discarded (long runtime / nontrivial env setup) → 106 → expert validation revises 41 instructions and removes 3 unrepresentative tasks → 103 → annotator cross-verification (verify tasks not composed by themselves, execute programs to reproduce results) refines 29 annotations and discards 1 task irreplicable due to randomness → **102 final tasks**. Contamination/shortcut mitigation: (1) randomly remove five data points from each test set (skipped where it breaks dataset completeness, e.g., a geographical map) so memorized automatic data loaders misalign and fail; (2) for model-development tasks, re-split dataset, keep test labels only for evaluation, replace with dummy values (e.g., -1). Expert validation via questionnaire (Appendix G): validate realism, review instruction language, provide up to three knowledge pieces, revise rubrics.

**2.3 Evaluation (lines 259–315).** Execution pipeline: conda env initialized with seven packages (numpy, pandas, matplotlib, pytorch, tensorflow, rdkit, tf_keras); pipreqs analyzes generated program; pip-tools plus hand-crafted rules configure env. Four metrics: **VER** (valid execution + correct output filename; binary), **SR** (output meets task-specific success criteria; binary; conditioned on valid execution — SR=0 if execution errors), **CBS** (CodeBERTScore F1 vs annotated program; set to 1.0 when SR=1), **Cost** (average USD per task). Table 1 success-criterion examples: Clintox multitask model must reach ≥0.77 test ROC-AUC; DAVIS drug repurposing top-5 must match gold top-5; IMU sleep endpoints must be `math.isclose` to gold; Toronto fire-station map figure must score ≥60 from the GPT-4o judge. Figure evaluation: GPT-4o judge with Yang et al. (2024b) prompt comparing generated figure to ground truth; 3 sampled responses averaged "for evaluation stability"; justified by citation that it "correlate[s] reasonably well with human raters" (no in-paper agreement number). Rubric-based evaluation: five stages (Data Loading, Data Processing, Modeling or Visualization, Output Formatting, Output Saving); GPT-4o drafts milestones/points, expert refines; used here only for *human* evaluation; automating it (LLM judge) flagged as future work.

**2.4 Comparison with Existing Benchmarks (lines 316–330, Table 2).** TaskBench 28,271 synthetic tasks; SWE-Bench 2,294; BioCoder-Py 1,126; ML-Bench 260; MLAgentBench 13; DiscoveryBench-Real 239 (6 subjects); SciCode 80 (5 subjects); BLADE 12 (6 subjects); ScienceAgentBench 102 (4 subjects, file-level generation, heterogeneous data, shortcut prevention ✓). Claims to be one of only two benchmarks (with SciCode) mitigating contamination/shortcuts. Defends "medium scale of 102 tasks" as "reasonable to evaluate agents, considering the annotation difficulty and evaluation cost."

**3 Experimental Setup (lines 331–373).** LLMs: Llama-3.1-Instruct-70B, -405B, Mistral-Large-2 (123B), GPT-4o (2024-05-13), Claude-3.5-Sonnet (2024-06-20); all temperature 0.2, top_p 0.95, 0-shot. Plus OpenAI o1-preview (o1-preview-2024-09-12) with default hyperparameters, direct prompting and self-debug only (incompatible with OpenHands as of 10/24/2024). Frameworks: direct prompting (one pass, no environment); OpenHands CodeAct v1.9 (Python interpreter, bash, web browser; large unified action space); self-debug (re-implemented: no reflection generation, early exit on two identical consecutive programs, pipreqs+pip-tools env setup, no pre-initialized basic packages for fairness). **Three independent runs per task; best run selected by max SR, then max VER, then max CBS, then min Cost; reported metric is the average of selected runs.** Mean±SD of the three runs in Appendix E.1.

**4 Results and Analysis / 4.1 Main Results (lines 374–485, Table 3).** Best-of-3 headline numbers (SR/CBS/VER/Cost): see Reported results below. Findings: (1) Execution feedback is necessary — direct-prompting Claude-3.5-Sonnet solves 16.7% (text; Table 3 shows 17.7) alone and 20.6% (table: 21.6) with knowledge; self-debug nearly doubles SR (16.7→32.4, 1.94x) and with knowledge yields +13.7 SR (20.6→34.3) and +45.1 VER (41.2→86.3). (2) Self-debug beats OpenHands CodeAct for 4/5 LLMs (GPT-4o the exception; GPT-4o uniquely uses the web browser tool); Claude self-debug solves 10.8% more tasks than Claude OpenHands at 17x lower cost ($0.958→$0.057). (3) Expert knowledge raises SR/CBS for most agents but *lowers* VER for most (unfamiliar specified tools cause incorrect/hallucinated API usage; without knowledge agents emit executable-but-meaningless programs, e.g., empty figures). (4) Complexity analysis: mean gold-program length 58.6 lines; >75% of succeeded tasks have shorter-than-mean gold programs. Failure breakdown: Bioinformatics/Comp-Chem failures concentrate in data processing + model development (heterogeneous data: cell images, molecules, genes); GIS/Psych failures in discipline-specific tools (Geopandas, Biopsykit) with hallucinated APIs. Authors conclude agents "cannot yet automate data-driven discovery tasks or the full research pipeline, in contrast to claims made in recent work such as Lu et al. (2024)."

**4.2 Human Evaluation (lines 486–531, Figure 4).** Rubric-based human evaluation of all 102 programs from Claude-3.5-Sonnet self-debug + knowledge. Each program rated by two different evaluators drawn from the data-collection annotators; binary marking of rubric items; stage scores normalized 0–100; final score = average of the two raters. Evaluators are hidden from execution results and success outcomes (partial-credit purpose), which admittedly introduces noise: equivalent-but-different solutions (random forest vs neural net) can be under-credited because rubrics derive from gold programs; figure-format judgments (colors, scales, labels) show "subjective variance." Results: data loading and processing discriminate success vs failure — nearly all successful programs get perfect data-loading ratings while 25% of failed programs score below 50 there; for data processing, failed programs skew to 20–50; in modeling/visualization the successful median sits at the failed distribution's 75th percentile; output formatting and saving show no difference between groups. No inter-rater agreement statistic is reported.

**5 Conclusion (lines 532–541).** Restates: 102 tasks, 44 publications, 4 disciplines, 9 experts; best agent 34.3% with knowledge; advocates agents as assistants for tedious tasks plus "more rigorous assessments of such agents."

**Ethics Statement (lines 544–568).** Licenses respected; two copyrighted repos (rasterio, matminer) believed compatible; removal requests welcomed. Safety: tasks are property prediction/feature analysis/visualization, no synthesis; agents not connected to lab hardware; outputs are self-contained Python programs on public data.

## Benchmark anatomy

- **N items:** 102 tasks (funnel 110 → 106 → 103 → 102), from 44 peer-reviewed publications / 31 repositories, 4 disciplines (Bioinformatics, Computational Chemistry, Geographical Information Science, Psychology & Cognitive Neuroscience). Sub-task categories per Figure 1; each task = one or more sub-tasks, all required.
- **Construction:** 9 graduate-student annotators adapt real published code into self-contained tasks (identify code example → collect data → adapt reference program → implement executable success criteria + GPT-4o-drafted rubrics → write instruction/dataset info). Annotated programs "extracted as is" then minimally revised, not written from scratch or model-generated.
- **Item authorship:** student annotators author instructions/adaptations; source programs authored by original publication authors; rubrics drafted by GPT-4o and revised by experts; knowledge authored by 9 experts (senior PhD students and professors).
- **Validation/review:** two-stage: (a) expert questionnaire — realism check, instruction-language revision (41 revised), knowledge provision, rubric revision, 3 tasks dropped; (b) annotator cross-verification — non-authors re-execute programs to reproduce results, 29 annotations refined, 1 task dropped for irreproducibility under randomness.
- **Human baseline:** none for task success. The only human-effort numbers: ≥2.5–3 hours/task for trained annotators to adapt code (vs ~10 min agent draft). No expert/human pass-rate under benchmark conditions.
- **Contamination defenses:** (1) delete 5 random test-set points per dataset (skipped when it breaks completeness), so memorized automatic loaders misalign; (2) re-split + dummy test labels (-1) for model-development tasks, so label-copying shortcuts fail. Case-studied working in Appendix F.2/F.4. Datasets/programs remain public otherwise.
- **Scoring:** binary SR from task-specific executable criteria (metric thresholds like ROC-AUC ≥0.77 established by 5 gold-program runs; exact/`math.isclose` matches; figure ≥60 from GPT-4o judge); VER binary; CBS continuous but overwritten to 1.0 when SR=1; cost in USD. Non-figure criteria fully programmatic.
- **Judge design:** GPT-4o judge only for figures, using MatplotAgent's prompt, comparing to ground-truth figure, 3 sampled responses averaged; correlation with humans asserted by citation only — no in-paper agreement statistic. Rubric-based (5-stage) evaluation is human-only in this paper (two raters, average, no kappa reported); automating it is named future work.
- **Statistical reporting:** 3 independent runs per task; headline = per-task best-of-3 (selection order SR, VER, CBS, cost); Appendix E.1 gives mean±SD over runs. **No confidence intervals, no significance tests, no clustering by source publication, no per-task variance reporting.** SD captures run-to-run noise only, not the n=102 sampling error.

## Limitations

**Admitted by the authors (mostly Appendix A, Sections 2.4/4.2):**
- Only the code-generation slice of scientific work is assessed; other capabilities (literature, ideation, experiment planning) deferred.
- CodeBERTScore and the GPT-4o figure judge "are not perfect yet."
- Python-only, because annotators couldn't confidently adapt R/Stata/Matlab despite more such programs existing.
- 10-minute execution cap biases against large-scale data and complex methods.
- Four disciplines chosen partly by convenience (open data abundance, expert access).
- 102 tasks is "medium scale," defended on annotation/eval cost grounds.
- Human rubric evaluation is noisy: rubrics derived from gold programs under-credit equivalent alternative solutions; figure-format judgments are subjective; raters blinded to outcomes.
- Rubric-based scoring is not automated; o1 comparison is explicitly caveated (different hyperparameters, extra reasoning tokens, "might be unfair to compare").

**Observed, not admitted:**
- **Headline inflation by aggregation choice:** the abstract's 32.4/34.3/42.2 are best-of-3 with selection *on the evaluation metric itself*; mean-of-3 is 22.9/27.8/27.1 — a ~5–10-point gap never surfaced in the abstract. "Given three attempts" is doing heavy, quiet work.
- **No inferential statistics at all:** no CIs on SR (at n=102, 32.4% carries a ±~9-point 95% binomial CI; many Table 3 gaps between adjacent models are within noise), no significance tests for framework/knowledge comparisons, and no clustering although 102 tasks come from only 44 publications (~2.3 tasks/publication sharing code style, data, and tooling), so the effective independent n is well below 102.
- **Internal inconsistency:** Section 4.1 text uses 16.7/20.6 for Claude direct prompting while Table 3 reads 17.7/21.6 — un-reconciled prose-vs-table drift.
- **Contamination defenses are partial:** the 5-point deletion is skipped where it breaks data; it only defeats *loader-level* memorization — an agent that memorized the pipeline but reads files manually passes untouched; datasets and gold programs remain publicly listed in Appendix J (post-publication, the benchmark itself becomes training data; no held-out/refresh plan is described).
- **Judge chain-of-trust:** GPT-4o both drafts rubrics and judges figures while GPT-4o is also an evaluated system — self-preference risk is never discussed; the figure threshold (≥60) is unjustified; no in-paper human-agreement number for the judge.
- **Success thresholds rest on 5 gold runs:** for stochastic training tasks, a 5-run minimum (e.g., ROC-AUC ≥0.77) is a thin basis for a binary pass line; borderline flakiness is unquantified (they did drop one task for irreproducibility, showing the risk is real).
- **CBS is a hybrid:** overwriting CBS to 1.0 when SR=1 conflates outcome and similarity, making CBS columns hard to interpret; CBS also rewards resembling *one* reference in an admittedly open-ended task space.
- **No human success baseline:** the 2.5–3 hour figure is annotation effort, not a measured expert pass rate under benchmark conditions; "agents reach 32% while humans reach ~100%" is implied, never measured.
- **Expert-knowledge leakage is self-policed:** the questionnaire permits "minimal leak" (e.g., decision boundary 0.6) at the expert's discretion; with-knowledge numbers therefore mix hinting levels of unknown strength across tasks.

## Implications for CRUCIBLE-CHAIN

1. **Publish the aggregation rule and make mean-of-k the number of record.** SAB's best-of-3 headline (32.4%) sits ~10 points above its own mean-of-3 (22.9%) because run selection uses the scoring metric itself; the abstract quietly reports the optimistic one. For CRUCIBLE-CHAIN, pre-register that the metric of record is mean pass rate over ≥3 repeats with a CI, and report best-of-k only as a separately-labeled pass@k diagnostic. Add a build check that every number in prose is generated from the results table — SAB's 16.7-vs-17.7 text/table drift shows even careful groups ship inconsistencies.

2. **Answer the scale question with clusters, not instances — SAB is the cautionary datapoint.** SAB's n=102 gives ±~9-point 95% binomial CIs, too wide to separate mid-tier models, and its 102 items cluster into 44 publications without any cluster adjustment. CRUCIBLE-CHAIN's current 8 templates x ~18 instances is far more concentrated (8 clusters): cluster-robust or template-bootstrap CIs will have ~7 degrees of freedom and be nearly useless. Actionable target: to distinguish single-digit rates (e.g., 4% vs 10% at alpha=0.05, power 0.8) you need roughly 250–350 *effectively independent* items per condition; with within-template correlation, plan for ≥30 independent templates with ~10–15 instances each (~300–450 items/condition), and always report the template-level bootstrap CI, not the instance-level binomial.

3. **Keep method recipes out of the base prompt; make hints a separately-scored condition with anti-leak rules.** SAB deliberately keeps instructions "concise and avoid unnecessary details," and moves method hints into an optional expert-knowledge condition with explicit anti-leak instructions to experts ("provide documentation, not code lines"; "suggest a range... instead of specifying the parameters"). The measured effect of hints was small (+1.9 SR for the best agent) and sometimes negative on VER. Since CRUCIBLE-CHAIN saturated precisely because prompts leaked method recipes and answer menus, adopt SAB's split: a bare condition (goal + data only) as the primary metric, and, if desired, a "hinted" condition whose hint text passes a written leakage rubric (no stage-level procedures, no candidate-answer enumerations, ranges instead of values) and is audited per-instance.

4. **Add shortcut canaries and a no-data ablation to certify the deleaked benchmark.** SAB's two perturbations (delete 5 test points; dummy labels) exist to make memorized loaders and label-copying *visibly fail*, and Appendix F.4 shows one catching DeepPurpose's auto-loader. CRUCIBLE-CHAIN's generator already defeats corpus contamination, but the saturation event shows prompt-level leakage is its real threat. Concrete tests to run each release: (a) score frontier models given the prompt but *withholding the generated data* — pass rates above chance prove the prompt alone encodes answers; (b) plant instances whose correct answer contradicts the template's modal answer, so recipe-following without data fails; (c) verify planted-defect and flawed-premise instances flip the correct output relative to the clean control for the same surface prompt.

5. **Log per-stage outcomes even under non-compensatory scoring, and prune non-discriminating stages.** SAB's 5-stage rubric evaluation found all discrimination lives in early stages (data loading/processing; 25% of failed programs scored <50 on loading) while output formatting/saving discriminated nothing. For CRUCIBLE-CHAIN's 5–8 stage chains, record first-failing-stage and per-stage pass for every run: it identifies which "attractive wrong path" actually attracts (and which stages are dead weight that only add run cost), lets you rebalance difficulty across the chain, and provides the partial-credit diagnostic axis without weakening the all-stages-must-pass headline metric.

6. **Stay fully deterministic on scoring; treat SAB's judge usage as the anti-pattern to cite.** SAB is programmatic everywhere it can be (executable criteria, `math.isclose`, thresholds set by 5 gold runs) and falls back to a GPT-4o judge only for figures — with a bare "≥60" threshold, 3-sample averaging, no in-paper human-agreement statistic, and the judge model doubling as an evaluated system. CRUCIBLE-CHAIN's constructed-truth design means every stage answer is computable; preserve that (no LLM judges anywhere in the scoring path), and when writing up, contrast against SAB's figure-judge to argue the near-zero label-error advantage. Also copy the good part: SAB set metric thresholds from repeated gold runs — CRUCIBLE-CHAIN's generator determinism should be verified analogously (re-run generator from spec N times, byte-identical answers) and stated as a claim with evidence.

7. **Adopt SAB's two-stage independent verification, and extend it for the refusal condition.** SAB's QC — expert questionnaire (revise 41, drop 3) plus non-author annotators re-executing every task (refine 29, drop 1 for irreproducibility) — caught real defects at ~40% incidence (revisions) even in expert-sourced material. For CRUCIBLE-CHAIN: each template gets a reviewer who didn't author it, who re-derives at least one instance's full 5–8 stage answer chain from the spec by hand; for flawed-premise instances, a blinded reviewer must independently flag the premise as flawed (validating that refusal is *discoverably* correct, not an ambush). SAB has no refusal-correct condition at all — that's CRUCIBLE-CHAIN's differentiator; instrument false-refusal rates on clean controls to prove models aren't gaming the third condition.

8. **Report cost as a first-class metric and budget the scale-up with it.** SAB's cost column changed its conclusions (self-debug beats OpenHands at 1/17th the cost; o1's +10 SR costs >10x), citing Kapoor et al. that agent evaluations must jointly report cost and performance. CRUCIBLE-CHAIN's recommended scale-up (≥30 templates x ~12 instances x 3 conditions x ≥3 repeats x several models ≈ 30k+ runs) makes per-run cost logging and a cost-per-confirmed-discrimination figure (dollars to statistically separate two models) part of the scale answer the sponsor is asking for.
